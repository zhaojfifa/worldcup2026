# Growth P0 — Compliance Note

## 1. What Growth P0 IS
A manual, operator-executed, design-and-SOP-only growth layer for the MVP-2 small private trial:
screenshots of already-guarded live surfaces shared by hand into Owner-approved channels, with
verbatim guard-passed LLM copy, channel-level manual source tags, and full send evidence
(queue mark-sent + screenshot + log). It grows attention to the strong-judgment loop
(赛前看方向 → 临场看变量 → 赛后看校准) and to the group where the 30-minute rescore lands.

## 2. What it is NOT
Not a referral program. Not an attribution system. Not a reward scheme. Not a payment or token
feature. Not automation. No message is generated, scheduled, or sent by software; no user is
tracked; no one earns anything for sharing or joining.

## 3. Why no Track B runtime
Track B (scout/referral mechanics) remains DESIGN-ONLY by Owner order. Every Track B mechanism
(invite codes, shadow users, reward grants, QR attribution) requires its own Owner GO, its own
guard wordlists, and its own compliance review BEFORE any table/route/UX exists. P0 deliberately
proves the growth loop with zero runtime so that the trial cannot leak into incentive mechanics
by accident.

## 4. Why no betting/payment/reward mechanics
Compliance floor (CLAUDE.md §4–§5, non-negotiable): 不做博彩 · 不做现金投注 · 不承诺命中 ·
不承诺收益 · MTC 仅平台积分（不可提现/不可转让/不可交易）. Betting-adjacent growth mechanics
(odds content, paid picks, commission referral, recharge incentives) are the exact failure mode
this product is designed to avoid; the external-expectation layer exists as INTERNAL signal only,
projected through a fixed customer-safe vocabulary with scanner enforcement in 4 languages.

## 5. Conditions before ANY runtime growth feature can be considered
1. Trial evidence: ≥1 full fixture cycle (pre-match send → T-30 update → recap follow-up) with
   recorded feedback per channel tag, no compliance incident.
2. Owner GO on a written runtime design (Track B doc or successor) naming exact tables/routes.
3. Guard implementation FIRST (growth wordlists in 4 languages + scanner coverage of the new
   surface) before the surface itself ships.
4. Channel-level attribution stays the ceiling unless Owner explicitly approves user-level
   mechanics with a privacy note.
5. Rewards, if ever, are MTC-only within the existing 不可提现/不可转让/不可交易 frame, manual
   grant, capped — never cash, never commission, never tied to betting outcomes.
6. PR review on a dedicated branch; no growth runtime rides along in an unrelated PR.
