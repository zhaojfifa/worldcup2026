# Growth P1.3 — Match Sync & Daily Fixture Registry

> Owner verdict 2026-06-13: P1.2b fixed runtime freshness for KNOWN fixtures, but the product did
> not sync the real daily slate — finished matches (Canada 1-1 Bosnia, USA 4-1 Paraguay) were
> invisible. The lifecycle gate can only protect fixtures it knows about; it cannot discover
> missing matches. P1.3 adds the daily fixture registry sync layer. No auto-send · no betting/
> trading vocab · no payment · no DB schema change · no invented scores or fixtures.

## What it does

`scripts/mvp2_match_sync.py sync --date YYYY-MM-DD` discovers the day's slate and writes:
- `docs/data_audit/mvp2_match_sync/daily_fixtures_YYYYMMDD.json` — the registry (one row per
  fixture: external_game_id / internal_fixture_id / teams / group / kickoff / status / score /
  source / lifecycle_state / pre_match_allowed / recap_needed / recap_ready / package_today_allowed
  / hero|recap|next_candidate / reason).
- `docs/data_audit/mvp2_match_sync/recap_queue_YYYYMMDD.json` — completed fixtures needing/holding a recap.
- `frontend/src/data/dailyFixtures.generated.json` — the homepage active manifest (renderable
  fixtures only, so the hero can always back a real surface).

Source modes: **manual** (default — parses `manual_scores_YYYYMMDD.md`, the operator/Owner slate;
no score invented, unconfirmed = `unknown`) and **fetched** (`--source fetched`, best-effort
API-FOOTBALL enrichment that never overwrites a confirmed manual score — records a conflict instead).

Every fixture is run through the canonical lifecycle (`scripts/mvp2_fixture_lifecycle.py`), the
same spec as the backend (`lifecycle.py`) and frontend (`freshness.ts`).

## Integration

- **Homepage hero** is now sourced from the registry manifest (`activeFixtureEntries()` →
  `pickActiveFixture`), not a hardcoded list. Priority: live → earliest pre-match → latest
  recap-ready → recap-pending → empty. recapReady is recomputed LIVE from the bundled narrative.
- **Package refresh** (`mvp2_growth_cli.py refresh`) chooses today/next/recap fixtures FROM the
  registry (`registry_sourced: true`). A finished fixture never yields a today package; a synced
  fixture with no narrative → `needs_narrative` + `operator_next_step` (never fabricated).
- **Scanner** `scripts/check_match_sync_freshness.py` fails if a completed fixture is missing from
  the recap queue, the hero uses a non-registry fixture, a today package targets a finished fixture,
  a known completed match is absent from the registry, a score conflicts with manual input, or the
  frontend hero is hardcoded.
