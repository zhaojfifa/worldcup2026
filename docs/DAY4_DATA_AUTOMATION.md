# Day 4 — Data Automation + Baseline Predictor

_Last updated: 2026-06-02_

Upgrades the seed/mock pipeline so fixtures can be **auto-synced from
API-FOOTBALL** and predictions are **generated by a baseline rules model**.
No frontend change; no API response-shape change.

---

## What shipped

| Area | Endpoint / module |
|------|-------------------|
| Data-source status | `GET /api/v1/data-source/status` |
| Admin fixtures sync | `POST /api/v1/admin/sync/fixtures` (header `x-admin-token`) |
| Single-match recompute | `POST /api/v1/matches/{id}/refresh` |
| API-FOOTBALL connector | `app/services/data_sources/api_football.py` |
| Fixtures sync job | `app/jobs/fixtures_sync.py` |
| Baseline predictor | `app/services/modeling/baseline.py` |

## API-FOOTBALL usage

The connector calls API-FOOTBALL v3 with the `x-apisports-key` header:

- `GET /status` → drives `/api/v1/data-source/status`
- `GET /fixtures?league={WC_LEAGUE_ID}&season={WC_SEASON}` → fixtures sync
- `GET /fixtures/lineups?fixture={id}` → reserved for T-35min LiveCorrection (Day 5)

If the key is not configured, every path degrades gracefully to mock mode
(no crash, clear `message`).

### Sync behaviour
- Teams upserted by `api_id`; matches upserted by `external_id = "AF-<fixtureId>"`.
- Existing rows are **updated**, never duplicated.
- Newly inserted matches also receive a baseline prediction so they appear in
  `/api/v1/matches` immediately.
- Returns `{ inserted, updated, skipped, errors[], total, mock_mode }`.

## Baseline predictor

`app/services/modeling/baseline.py` is a **deterministic rules model**, not ML.

- **Inputs (placeholders today):** team strength, recent form, risk factors,
  lineup status.
- **Outputs:** `prob_home / prob_draw / prob_away` (integers that **always sum
  to exactly 100** via largest-remainder rounding — no 45+27+37 bugs),
  `confidence`, `risk_level`, `risk_note`, `recommended_score`.
- **Fallback:** when inputs are missing/zero it falls back to a stable, balanced
  distribution rather than failing.
- **Stable:** strengths are derived deterministically from team names, so
  repeated `refresh` calls are reproducible.

### Future upgrade path
The `predict(PredictorInput) -> dict` signature and the `Prediction` table shape
are intentionally stable. The rules core can be replaced with
**CatBoost / LightGBM** for probabilities and **SHAP** for factor contributions
without touching the API or the frontend.

## Scheduling note (important)

`app/jobs/fixtures_sync.py` is invoked **on demand** via the admin endpoint.
On **Render Starter**, in-process timers (APScheduler etc.) are **not** a
production scheduler — they don't survive restarts/scale events and can run
multiple times. For real operations, run the sync from a dedicated
**Render Cron Job** or **Background Worker** that calls the same
`sync_fixtures()` function (or hits the admin endpoint with the token).

## Local test commands

```bash
cd backend
uvicorn app.main:app --reload          # ensure repo-root .env has ADMIN_API_TOKEN

# health
curl http://localhost:8000/api/v1/health

# data-source status (safe; never shows the key)
curl http://localhost:8000/api/v1/data-source/status

# admin fixtures sync (401 without a valid token)
curl -X POST http://localhost:8000/api/v1/admin/sync/fixtures \
  -H "x-admin-token: $ADMIN_API_TOKEN"

# recompute one match with the baseline model
curl -X POST http://localhost:8000/api/v1/matches/1/refresh

# list matches (unchanged shape)
curl http://localhost:8000/api/v1/matches
```

When `API_FOOTBALL_KEY` is unset, `sync/fixtures` returns
`mock_mode: true` with a clear message and makes no external calls.
