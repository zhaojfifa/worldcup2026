## 一、产品定位

**正式定位：2026 世界杯 AI 足球情报社区。**

面向越南、缅甸及东南亚足球用户，提供基于数据模型的赛前观点、胜率变化、风险提示、
临场阵容修正与球迷互动任务。平台核心**不是提供投注建议**，而是提供 **AI 数据观点、
赛事情报、风险解释与社区化内容运营**。

**用户侧正式术语（统一使用）：** AI 足球情报社区 · AI 赛事情报 · AI 数据观点 ·
AI 倾向 · 风险提示 · 临场修正 · 情报更新 · 球迷任务。

**用户侧禁止术语：** 决策社区（内部讨论可用「情报/研判」，对外一律用「情报社区」）。

**定位升级逻辑：** 工具型产品按任务被使用后即流失；情报社区具备每日仪式、社交证明
与持续内容，正好补齐当前缺失的「决策引导 / 情绪氛围 / 回访理由」三层。升级不改变
合规底线，反而让「售卖情报流与社区服务」的表述比「售卖预测结果」更稳健。

## 二、现有产品判断（基于 MVP v0.4 真实状态）

**当前已完成：**
- 前端 Render 部署
- 后端 Render 部署
- PostgreSQL 数据库
- API 数据联调（前端 `VITE_USE_MOCK=false` 可请求线上后端）
- UI / Copy Enhancement
- API-FOOTBALL connector
- baseline predictor（概率归一化稳定）
- admin protected fixtures sync（`x-admin-token`）
- match refresh API（`POST /api/v1/matches/{id}/refresh`）

**当前缺少（按运营优先级）：**
1. **决策引导**：用户看完胜平负概率后，仍缺少一句清晰的「AI 倾向」。
2. **情绪氛围**：东南亚用户更吃热点、强标题、爆冷榜、社区热度；当前首页平铺，无焦点。
3. **回访理由**：缺少战绩、连胜挑战、排行榜、每日更新等留存机制。
4. **运营素材**：TikTok / Facebook / Telegram / Zalo 需要可复制文案与分享卡，目前无。
5. **本地化**：当前仅中文；需越南语优先、缅甸语后续。

**判断结论：** 引擎（fixtures → baseline prediction → API → 移动端）已打通且上线，
视觉层已具备体育 App 观感；下一步的核心不是继续堆数据，而是补「行为层」——
让用户一眼看懂 AI 倾向、产生情绪与好奇、并有理由明天再来。

## 三、首页新版设计方向

**正式命名：今日 AI 情报流。**

设计原则：一个明确焦点 → 可快速扫读的信号 → 留存闭环入口。以「排序信息流」替代
当前的「等权卡片列表」。

### 模块顺序与字段

**1. 今日 AI 最强信号（C 位）**
- 作用：决策引导 + 情绪焦点。
- 字段：比赛双方、AI 倾向（`ai_pick_label`）、信心星级（`confidence_star`）、
  胜平负概率、核心风险（一句）、「查看 AI 观点」/「解锁完整分析」按钮。
- 用户侧文案：使用「AI 最强信号」或「今日最高信心」，**不使用「最稳」**。
- 数据来源：现阶段由现有 `Prediction` 派生（取最高 confidence 或 `tag=focus`）。

**2. 今日比赛简表**
- 作用：低认知负荷，3 秒扫完。
- 字段：时间、队伍、AI 倾向、风险标签、热度。
- 数据来源：现有 `/api/v1/matches`；`ai_pick_label` 由输出层派生。

**3. 今日爆冷风险 TOP3**
- 作用：传播性 + 用户好奇心。
- 字段：排名、比赛、爆冷分（`upset_score`）、一句提示。
- 用户侧文案：使用「爆冷风险 / 风险升高 / 需谨慎关注」，
  **不使用「翻车 / 稳赚 / 必中」**。
- 数据来源：由 `risk_level` + 概率分布 + `tag=upset` 派生。

**4. AI 情报战绩**
- 作用：信任增长点。
- **生产环境不得展示未标注的虚假战绩。**
- 现阶段表述：「真实赛果回灌后开放」；若处于**运营预览态**，必须清晰标注「示例数据」。
- 字段：昨日命中/总数、近 7 天命中率、临场修正后提升。
- **必带免责声明：** 「历史表现不代表未来结果，仅供数据分析和球迷娱乐参考。」

**5. 社区热门选择**
- 作用：社交证明 / 跟风心理。
- 首版做**轻社交证明**，不做真实 UGC。
- 字段：热门关注比赛、讨论热度、可显示「社区热度即将上线」（数据能力建设中）。
- 后续接入真实用户行为数据。

**6. Token / 连胜挑战 / 排行榜入口**
- 作用：回访机制入口。
- MTC 始终定义为平台积分：**不可提现、不可转让、不可交易**。

## 四、详情页新版设计方向

详情页为转化核心，AI 结论为主角，其余模块为支撑。保留现有组件（胜率条、
LINEUP WATCH、特征贡献），重排与重述。

**模块顺序：**

1. **AI 结论卡（置顶）**：AI 倾向、推荐比分、信心星级、风险等级。
2. **胜率图**：主胜 / 平局 / 客胜，沿用当前胜率条或仪表盘表达。
3. **为什么 AI 这么判断**：2–3 条短理由；现阶段规则派生，后续由 Kimi / DeepSeek
   生成更自然的战术解释。
4. **风险提示**：伤病、反击、临场首发、裁判尺度、战意等；提升专业度并降低误导风险。
5. **LINEUP WATCH**：保留临场 30 分钟修正；强调首发公布后，AI 根据核心球员、
   阵型变化、替补强度重新计算胜率。
6. **付费解锁 / 社群引导**：单场 ¥39 / 390 MTC；月度社群 ¥199 / 月。
   **暂不引入 ¥19 或 ¥399 档位。**

**免费 / 付费内容边界：**
- 免费：AI 倾向标签、信心星级、胜率图、1 条理由预览、基础风险标签、比分倾向（范围/模糊）。
- 付费：精确推荐比分、完整 2–3 条理由、风险等级与详细风险、临场修正推送。
- 该边界与现有 `free_note`（免费）/ `Report`（付费）数据划分一致，无需改表结构。

**东南亚短句式文案示例：** 「AI 倾向：主队不败」「信心：★★★★☆」
「风险：客队反击强」「首发公布后 AI 会重算，记得回来看」。

## 五、后端与 API 设计建议（不写代码）

**原则（来自 CLAUDE.md）：不改现有响应结构；新能力一律新增端点。**
必须保证以下端点字节级兼容、不被破坏：
`/api/v1/matches`、`/api/v1/matches/{id}`、`/api/v1/reports/{id}`。

**推荐新增（后置实现）聚合接口：** `GET /api/v1/home/summary`

返回（聚合，新增端点，不影响既有 shape）：
- `top_pick`、`today_matches`、`upset_alerts`、`performance`、`community_heat`

**数据来源判断：**

| 数据 | 现有可派生 | 需新增表 | 适合阶段 |
|------|-----------|---------|---------|
| `top_pick` | 是（Prediction：最高 confidence / focus） | 否 | Phase A 派生 / Phase B 聚合 |
| `today_matches` | 是（现有 `/matches`） | 否 | 现有 |
| `upset_alerts` | 是（risk_level + 概率派生） | 否 | Phase A 派生 / Phase B 端点 |
| `performance` | 否（需实际赛果） | 是（`MatchResult`） | Phase B（待真实赛果回灌） |
| `community_heat` | 否（需行为数据） | 是（`MatchEngagement`） | Phase B/C（数据能力建设中） |
| `rankings` | 部分（ChallengeEntry 有，但缺连胜/结算） | 是（`UserStreak`/榜单） | Phase C |

**接口节奏判断：**
1. `home/summary`：**后置到 Phase B**（Day 5 不做），首版以聚合现有数据 +
   战绩/热度为「待回灌 / 建设中」状态返回。
2. `upsets/today`、`performance/daily`、`community/heat`、`rankings`：Phase B/C
   按数据就绪度逐个开放。
3. 新增端点全部为**加法**，复用 `MatchListItem` 结构，`transform.ts` 可大量复用。
4. 新增表（`MatchResult` / `MatchEngagement` / `UserStreak`）均独立于预测内核，
   不触碰 `Match` / `Prediction` / `Report` 结构。

## 六、建模输出层设计（运营可读输出层）

在 baseline predictor 之上新增**派生输出层**（纯函数派生现有预测字段），
不改预测内核、不引入复杂 ML、现阶段不接真实大模型。

baseline 现有输出：`prob_home/draw/away`、`confidence`、`risk_level`、
`risk_note`、`recommended_score`。

**运营输出层字段：**

| 字段 | 现阶段规则派生方式 | 后续 LLM 优化 |
|------|------------------|--------------|
| `ai_pick_label` | 由概率分布映射：主胜偏强 / 主队不败 / 难分胜负 / 客胜偏强 / 可能爆冷 | 否（保持确定性） |
| `confidence_star` | `confidence` 0–100 → 1–5 星 | 否 |
| `upset_score` | 概率差小 + 热门方不稳 + `tag=upset` + 高 risk → 0–100 | 后续随数据细化 |
| `heat_score` | 现阶段由 `tag`/confidence 占位派生 | 后续接真实行为数据 |
| `volatility_score` | 由 `Report.trend_history` 波动或 `risk_level` 映射 | 后续数据驱动 |
| `live_sensitive_score` | 由 `risk_level` + 赛段（淘汰赛↑）派生 | 后续由阵容依赖度驱动 |
| `reason_bullets` | 由 `Report.features[]` 取主要贡献项，模板化短句 | **Kimi / DeepSeek** 生成自然语言 |
| `free_conclusion` | 仅标签 + 星级（不含精确比分） | 否 |
| `premium_teaser` | 已锁定项的数量/名称（精确比分 + 理由 + 风险评级） | 否 |

**要求：**
1. 先用规则生成。2. 不改预测内核。3. 不引入复杂 ML。4. 现阶段不接真实大模型。
5. 后续由 Kimi / DeepSeek 优化 `reason_bullets` 与 premium narrative。
6. **所有生成文本必须经过合规词过滤**（见第八章）：数值类字段保持规则确定性，
   仅自然语言字段交由 LLM，且经系统提示 + 生成后禁用词过滤双重约束。

## 七、运营内容系统设计

目标：让网站/API 成为运营内容工厂，支撑 TikTok / Facebook / Telegram / Zalo
每日 3–5 次发布，最大化自动化、最小化人工。

| 运营内容 | 数据来源 | API 自动生成 | 需人工编辑 |
|----------|---------|-------------|-----------|
| 今日 AI 三场速览 | top_pick + 后续两场 | 是 | 轻量标题 |
| 今日 AI 最强信号 | top_pick | 是 | 强标题 |
| 今日爆冷风险 | upsets | 是 | — |
| 临场修正截图 | LiveCorrection | 是（渲染卡片） | — |
| 昨日战绩复盘 | performance（待回灌后） | 真实赛果回灌后自动 | 语气 |
| 用户连胜榜 | rankings（建设中） | 数据就绪后自动 | — |
| 社群引导文案 | 模板 + 当日比赛 | 是 | 本地化措辞 |

**设计建议：**
1. **「复制运营文案」按钮：建议提供**（Phase A/C，成本低、价值高）。按比赛/按日
   输出合规短文案，自动附带免责声明。
2. **「生成分享卡」功能：建议提供**（Phase C）。信号 / 爆冷 / 临场修正 / 战绩卡。
   首版可前端渲染，托管接入 R2 为可选后置项（R2 当前未启用）。
3. **API 可自动生成：** 信号、爆冷、简表、临场修正卡、（赛果回灌后）战绩复盘。
4. **需人工编辑：** 强标题、本地化措辞、社区内容、强引导话术——机器产出骨架，
   运营补「氛围」层。
5. **本地化分阶段：**
   - 越南语优先（用户规模与足球线上度更高，Zalo 原生）→ Zalo + Facebook + TikTok VN。
   - 缅甸语后续（Facebook 主导、Telegram 私域）→ 缅文文案，初期范围更轻。
   - 前置工程：i18n key 化（`ai_pick_label`、风险标签、免责声明等均走翻译键），
     这是东南亚运营的关键前提（当前仅中文）。

## 八、合规边界

**用户侧营销文案禁止出现：**
下注 · 稳赚 · 必中 · 跟单 · 购彩 · 回报率 · 返奖 · 收益承诺 · 现金奖池 ·
Token 提现 / 转让 / 交易。
（运营文档中出现的「最稳一场 / 竞猜」等表述同样禁止；改为「今日最高信心 / AI 最强信号」。）

**允许使用：**
AI 倾向 · 数据观点 · 风险提示 · 社区热度 · 情报更新 · 积分挑战 · 球迷娱乐参考。

**特别要求：**
1. 「提现」只允许出现在「不可提现」合规声明中。
2. 出现「战绩 / 命中 / 连胜」时，必须附带：
   「历史表现不代表未来结果，仅供数据分析和球迷娱乐参考。」
3. MTC 必须始终描述为平台积分，不是金融资产；声明：不可提现 · 不可转让 · 不可交易 ·
   不作为金融资产 · 不承诺收益 · 不接入博彩。

**执行机制建议：**
- 前后端共用一份禁用词清单（`compliance` 工具），用于 LLM 生成后过滤与 CI 扫描。
- 战绩类数据：要么真实、要么明确标注（运营预览态/示例数据），**生产环境不得展示
  未标注的虚假战绩**。
- AI 倾向标签使用白名单词表（倾向 / 偏强 / 不败趋势 / 可能爆冷 / 难分胜负）。

## 九、实施路线

### Phase A — 前端优先，运营信息架构增强
- **目标：** 以现有数据 + 规则派生 + 合规占位，让首页/详情页升级为情报社区观感。
- **范围：**
  - 首页 C 位「今日 AI 最强信号」
  - 今日比赛简表
  - 爆冷风险 TOP3
  - 战绩模块占位（待真实赛果回灌；若展示则标注示例数据 + 免责声明）
  - 详情页「AI 结论卡」置顶
  - 前端派生 `ai_pick_label` / `confidence_star` / `upset_score`（置于 transform/输出层助手）
  - **不改后端 API**
- **风险：** 低（前端，可回退）。主要风险为占位战绩被误读 → 以「待回灌/示例数据」
  + 免责声明规避。
- **验收：** 见第十章。
- **是否影响线上：** 仅前端，安全可回退。

### Phase B — 后端聚合 API 与真实战绩
- **目标：** 用真实聚合与赛果支撑新首页。
- **范围：** `GET /api/v1/home/summary`；新增 `MatchResult` 表 + 赛果回灌
  （经 API-FOOTBALL 已结束赛事）；`performance/daily`；`upsets/today`；
  `community/heat`（数据能力建设中）。
- **风险：** 中（新表 + 回灌）；所有新端点保持加法、不改既有 shape。
- **验收：** `home/summary` 聚合正确；既有端点字节兼容；回灌幂等；战绩与存储赛果可对账；
  写操作受 admin 保护。
- **是否影响线上：** 加法端点，前端按需接入，对既有流程低风险。

### Phase C — 运营自动化与本地化
- **目标：** 更自然（部分 LLM）的情报 + 内容/分享/社区闭环。
- **范围：** `reason_bullets` 与 premium narrative 接 Kimi / DeepSeek（`AI_PROVIDER`
  切换）+ 合规过滤器；`community/heat` 与 `rankings`（新表 `UserStreak`）；
  「复制运营文案」「生成分享卡」；i18n（越南语优先、缅甸语后续）；R2 可选
  （分享卡托管）；Telegram / Zalo 内容转化辅助。
- **风险：** 较高（LLM 成本/延迟、生成文案合规、新行为数据）；以 feature flag +
  过滤器 + 规则兜底约束。
- **验收：** 生成文案 100% 通过合规过滤；LLM 失败回退规则；分享卡可渲染；越南语
  翻译键完整；连胜/榜单数据一致；flag 关闭时不影响线上。
- **是否影响线上：** 仅在 flag 开启时生效，默认关闭即无影响。
