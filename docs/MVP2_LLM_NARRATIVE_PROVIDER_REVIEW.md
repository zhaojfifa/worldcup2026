# MVP-2 — LLM Narrative Provider Review (DeepSeek vs Gemini)

> **Date:** 2026-06-10 · **Subject:** real DeepSeek (`deepseek-chat`) vs Gemini (`gemini-2.5-flash`) narratives
> for 855737, zh-CN + vi-VN, generated by `scripts/mvp2_generate_scoutscore_narrative.py` and **all four passing**
> `scripts/check_mvp2_llm_narrative_guard.py`. Artifacts: `docs/data_audit/mvp2_llm_narratives/855737.*.{deepseek,gemini}.json`.
> Both are **real LLM output** (`llm_provider` = deepseek / gemini), not mock.

Note: the **raw** first-round output of BOTH providers failed the guard (leaked factor keys like `team_strength`,
drifted schema `signal`/`detail`, dropped fields in vi). After tightening the prompt + naturalizing the input
(engineering's job — schema/prompts/guards), the **regenerated** output of both providers passed. The comparison
below is on the guard-passing version.

---

## Side-by-side
| Dimension | DeepSeek (`deepseek-chat`) | Gemini (`gemini-2.5-flash`) |
|---|---|---|
| 更像产品文案 (product-copy feel) | **强** — 标题「纸面碾压，效率翻车」punchy，像体育编辑 | 好，但偏正式/略长（「强队迷思」是亮点） |
| 更懂足球用户语言 | **强** — 「翻车」「冷门密码」等球迷语感 | 标准、清晰，球迷语感稍弱 |
| 更适合中文运营 (operator copy) | **强** — operator_copy 一句话、可截图、不啰嗦 | 偏长、偏「官方」，CTA 略带推销味（「洞察赛场风云！」） |
| 越南语自然度 | 自然、简洁 | 自然、更详细（基本持平，各有所长） |
| 更少工程味 | **强**（收紧后）| 干净（收紧后），source_ref_map 偏冗余（输入因子名 + 信号名都塞进去） |
| 更会保留证据边界 | 好 | **更全** — 多带 formation/lineups 来源；更明确把 xG/injuries 标为「下一场要看」 |
| 篇幅 / 密度 | 紧凑 | 更长、信息更全 |

## Recommendation
- **默认 provider：DeepSeek。** 产品文案 / 运营文案的「人话感」「可截图感」更强，hero 与 operator_copy 更适合越南/缅甸私域运营。
- **Benchmark / 备选：Gemini。** 当需要更完整的证据/边界铺陈（如带阵型来源、更细的 takeaway）时更合适，可作为对照或回退。
- **排除：Kimi**（既往比较：vi/mm 漏中文）。
- 两者都通过 guard；最终 provider 由 Owner 拍板。本轮前端**绑定 DeepSeek** 作为 `/recap` + `/evidence` 的叙事来源，
  Gemini 产物保留在 `docs/data_audit/mvp2_llm_narratives/` 供对照。

## Caveats
- 单场样本（855737），temperature 0.5；不同次生成会有措辞差异——这是叙事模型的预期行为，guard 负责守住边界。
- 这是历史回放样例的**赛后**叙事；非赛前预测、非命中宣称（`internal_notes` 保留 historical-replay/MISS 表述）。
- mock 仅在 provider 不可用 / guard 失败时作为**已标记**回退（`llm_provider=mock`），不是默认路径。
