## Editorial manifest override (the "small manifest fix", Owner-pre-authorized)
On the **currently deployed P1.5b bundle**, the homepage hero is chosen client-side by
`pickActiveFixture`, which ranks `recap_ready` ABOVE `recap_pending`, and the recap desk's featured
slot = `recapReady` items. Left mechanical, **Mexico (recap_ready) would become both the hero and
the featured recap**, demoting Brazil — exactly what Owner forbids. The only lever that does not
touch the frontend bundle is the manifest data. Applied to both the registry and the runtime
manifest:
- **Brazil 1489371**: `renderable=true`, `recapReady=false`, `heroCandidate=false`. Renderable keeps
  it in the client hero pool; with Mexico removed it is the only renderable entry → `pickActiveFixture`
  returns it as `recap_pending` → **Brazil is the hero (复盘准备中)**. `heroCandidate` stays false
  (a finished fixture is never a pre-match hero candidate — freshness guard).
- **Mexico 1489369**: `renderable=false` (removed from hero pool so it cannot outrank Brazil),
  `recapReady=true` (kept, so it stays the recap-desk **secondary** featured recap with 查看复盘),
  `heroCandidate=false`.
- Note: a re-run of `sync` will reset these derived flags (renderable/hero are auto-derived from
  narrative presence + recap state). This override is a one-shot for this slate. If this becomes
  recurring, fold an explicit editorial-selection field into P1.5c tooling (Owner-gated) rather than
  hand-editing.
